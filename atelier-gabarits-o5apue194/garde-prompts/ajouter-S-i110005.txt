LE CONTRAT DE COUCHE I (mot pour mot) :
loupe-05 · sha256 d'une gamme : l'héritage tls13 PAR LA CARTE · révision 1
Intention : le condensé SHA-256 d'une gamme du fichier ouvert —
l'héritage de la famille sha tls13 (M9, scellée 1.0.0) PAR LA CARTE :
les QUATRE blocs tls13-01..04 embarqués au build BYTE-IDENTIQUES à leur
scellé (R7), appelés par le plan d'adressage, JAMAIS une copie d'octets
ré-écrite. La gamme passe par fenêtres glissantes de 64 Kio
(TAMPON_CUMUL) : un fichier de 2 Gio se condense sans jamais tenir en
mémoire.
Contrat :
  pre  : P1 la session est ouverte (la poignée ≠ INVALIDE) ;
         P2 rcx = le décalage de gamme (≥ 0), rdx = la longueur (≥ 0) ;
         P3 décalage + longueur ≤ taille du fichier ;
         P4 r8 = la sortie, 32 o accessibles en écriture.
  post : Q1 la sortie = SHA-256(F[décalage .. décalage + longueur))
             — FIPS 180-4, la sémantique des blocs hérités (le contexte
             112 o de tls13-01 P1, tenu SUR LA PILE — rien ne survit au
             retour) ;
         Q2 LA COMPOSITION HÉRITÉE : tls13-01 (l'initialisation, UNE
             fois) puis, pour chaque fenêtre lue (SetFilePointerEx +
             ReadFile dans TAMPON_CUMUL, au plus CUMUL_FENETRE octets),
             tls13-03 (l'absorption), puis tls13-04 (la finalisation) —
             LA LISTE EST FERMÉE (tls13-02 vit à l'intérieur de
             tls13-03, l'héritage l'embarque avec) ;
         Q3 la gamme VIDE (longueur 0) rend le condensé du vide FIPS
             (e3b0c442…98ec4bf2) — le vecteur officiel, l'héritage le
             porte ;
         Q4 rax = 0.
  inv  : I1 L'HÉRITAGE PAR LA CARTE (charte § 2, R7) : les octets de
             tls13-01..04 au build == les octets du scellé 1.0.0 —
             l'oracle du build le constatera octet par octet ; la
             contrebande (une ré-écriture) est un refus de build ;
         I2 AUCUNE constante SHA re-déclarée au domaine (H0, le bloc
             64, la disposition du contexte vivent à tls13-01 — la
             source unique, T5) ;
         I3 la lecture passe par TAMPON_CUMUL — JAMAIS le tampon de
             vue du cadre (la vue est intacte pendant le calcul :
             l'invariant d'exclusion de famille) ;
         I4 le pointeur fichier est repositionné à CHAQUE fenêtre
             (SetFilePointerEx avant chaque ReadFile) — jamais une
             position héritée d'un autre bloc ;
         I5 l'IAT déclarée (D161) : SetFilePointerEx, ReadFile,
             GetLastError — la liste fermée ; registres non volatils
             rendus ; NOP, 0x90.
Échecs :
  E1 : sans session (P1) → verdict -4 SESSION, rax = -4.
  E2 : la gamme hors fichier (P3) → verdict -3 HORS-BORNES, rax = -3.
  E3 : la sortie inutilisable (P4 nulle) → verdict -5 ENTRÉE, rax = -5.
  E4 : ReadFile ou SetFilePointerEx en échec → verdict -6 SYSTÈME, le
