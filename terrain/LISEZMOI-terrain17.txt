LA NOUVELLE, EN PREMIER
-----------------------
Le jalon M4 a construit le tunnel TLS ces trois derniers jours : la poignée
de main Schannel, l'émission chiffrée, la réception déchiffrée, la session
complète — le tout noté, mesuré, prouvé, puis câblé dans proxy.exe
0.5.0-dev.2 (l'entrée du programme lance maintenant la couche M4 entière,
gardée par une porte d'intégrité qui protège AUSSI la zone neuve). Tout
cela vivait dans nos émulateurs. Il manque UNE chose : votre machine réelle.
C'est le rôle de terrain.17 : le kit embarqué transporte le NOUVEAU proxy,
et le test T4 joue les DEUX moitiés du critère M4 :

  (a) HTTPS SAIN — une requête « GET https://example.com/ » (forme absolue,
      le schéma dans la ligne de requête) traverse le proxy : le tunnel se
      chiffre, la page revient en clair au client. Le journal du proxy doit
      dire « tunnel chiffre etabli ».
  (b) CERTIFICAT INVALIDE — la même requête vers self-signed.badssl.com :
      Schannel doit refuser le certificat auto-signé, et le proxy doit
      répondre EXACTEMENT « HTTP/1.1 502 Certificat rejete » — 34 octets,
      pas un de plus — et dire « certificat rejete » au journal.

Le client qui parle la forme absolue https:// n'existe dans AUCUN outil
standard (curl envoie CONNECT et chiffre lui-même) : le superviseur pose
donc un petit script TCP (terrain_m4.ps1, composant système powershell.exe)
qui écrit la requête à la main et recopie la réponse. Le script est une
DONNÉE du plan — le superviseur ne contient pas un octet de client.
