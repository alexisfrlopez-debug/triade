LE PROTOCOLE TELEPHONE-ARM-1 (l'équation figée — le LISEZMOI fait foi).
Quatre cibles dans cet ordre : eq-constant (le CONTRÔLE POSITIF — la
comparaison 32 octets par OU masqué, aucun branchement sur le secret) ;
eq-branchue (le CONTRÔLE NÉGATIF — la sortie au premier octet divergent,
LE FAUX PATRON : l'instrument doit DÉTECTER la fuite, sinon il se
conteste lui-même) ; sha256-logiciel (la compression de dudect_v150.c —
la cible tls13-02 : état AMONT l'IV, bloc 64 LE SECRET) ; sha256-arm-sha2
(les instructions MATÉRIELLES FEAT_SHA256, SHA256H/SHA256H2 — UNE AUTRE
famille que la SHA-NI x86 ; elle ne vit que si le noyau expose « sha2 »
ET que le compilateur a accepté -march=armv8-a+sha2 : la double garde,
REFUS NOMMÉ sinon). Les classes : EGAL (le secret, copie de l'étalon)
contre DIVERGENT (le secret frais) pour les comparaisons — le cas
canonique de la divulgation par comparaison ; SECRET-FIXE contre
SECRET-ALÉATOIRE pour les compressions. Les échantillons ENTRELACÉS (à
chaque itération la première classe puis la seconde : le téléphone
gouverne sa fréquence, les deux classes vivent les mêmes fenêtres — la
différence nommée avec le kit-2 aux classes séquentielles). L'équation :
échauffement 100 paires ; LOT=512 (comparaisons) / LOT=4 (compressions) —
l'amplification, les compteurs de téléphone étant grossiers (CNTVCT_EL0,
≈52 ns le tick : la grandeur est « ticks », jamais « cycles », le repli
horloge est NOMMÉ si la lecture est refusée) ; N=60 puis 200 puis 400
dans cet ordre ; le t de Welch au seuil |t|>5 ; l'épreuve FIPS 180-4
« abc » EXACTE exigée des deux lecteurs AVANT toute mesure (fail-closed).

LA PREUVE DU LABORATOIRE — L'INSTRUMENT S'EST CONTESTÉ LUI-MÊME, DEUX
