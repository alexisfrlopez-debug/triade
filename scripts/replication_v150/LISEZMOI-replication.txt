LISEZMOI — LE KIT DE RÉPLICATION (v0.15.0, la commande ic09ydeli point 3)
==========================================================================

LA COMMANDE : « préparer l'exécution du protocole proposé — grille de
codage T/X finalisée, double annotation (second annotateur à
recruter : consigner le statut), κ de Cohen calculé dès les annotations
disponibles, critères d'acceptation pré-enregistrés inchangés ;
exécuter l'axe 'second domaine' au laboratoire si un second domaine
applicatif est réalisable, sinon le consigner comme en attente avec le
kit prêt ».

LES PIÈCES DU KIT (ce dossier, scripts/replication_v150/) :
  grille_tx.csv           LA GRILLE FINALISÉE — les cinq classes
                          terrain T1-T5 et les trois classes
                          laboratoire X1-X3, chacune avec sa définition
                          OPÉRATIONNELLE et ses exemples vécus (le
                          recul D189 : les défauts des douze runs
                          loupe + les artefacts de laboratoire) ;
  kohen_kappa_v150.py     LE CALCULATEUR κ — AUTOTESTÉ sur annotations
                          SYNTHÉTIQUES (trois cas au κ calculable à la
                          main : parfait +1, désaccord total −1,
                          partiel +0,4 — VERT) ; le κ réel se calcule
                          le jour des DEUX jeux (usage :
                          python3 kohen_kappa_v150.py ann1.csv ann2.csv,
                          le CSV : « id,classe ») ;
  ce LISEZMOI             les critères, les statuts, le mode d'emploi.

LES CRITÈRES D'ACCEPTATION PRÉ-ENREGISTRÉS (D189 — INCHANGÉS, la
commande le exige) :
  1. le jalon franchi : le réplicant mène UN jalon complet depuis le
     dépôt public (R1) / une application réelle neuve en un autre
     domaine (R2) / le port d'un bloc vers un profil non primaire (R3) ;
  2. les défauts codés : CHAQUE écart nommé est codé dans la grille
     (une classe au moins) — le compte exact, jamais une impression ;
  3. les classes T du réplicant ⊆ celles du premier développeur —
     une classe NOUVELLE est un RÉSULTAT, jamais un échec ;
  4. la DOUBLE ANNOTATION par deux codeurs indépendants, le κ DE
     COHEN ≥ 0,61 (substantiel) sur les items communs.

LES STATUTS (consignés — la commande l'exige) :
  R1 SECOND DÉVELOPPEUR  : au développeur — le dépôt public
     (Pimpalate-M/protocole-triade) est la pièce, la passation
     D13/D141 le modèle ; AUCUN réplicant recruté à ce jour ;
  R2 SECOND DOMAINE      : EN ATTENTE — le protocole exige une VRAIE
     commande applicative (jamais un exercice démonstratif) ; le kit
     est prêt (la grille, les critères, le calculateur) ;
  LE SECOND ANNOTATEUR  : À RECRUTER — aucun annotateur indépendant
     n'est disponible au laboratoire ; le κ sera calculé dès les deux
     jeux d'annotations disponibles (le calculateur est prêt et
     autotesté).

LE MODE D'EMPLOI DE LA DOUBLE ANNOTATION (le jour venu) :
  1. les DEUX codeurs codent SÉPARÉMENT la même liste de défauts
     (chaque ligne : un id stable, le défaut nommé, sa description) ;
  2. chacun produit son CSV (id,classe) — SANS consulter l'autre ;
  3. la confrontation : python3 kohen_kappa_v150.py ann1.csv ann2.csv
     — le κ, po, pe, et la LISTE DES LITIGES nommés ;
  4. les litiges se TRANCHENT par discussion documentée (la classe
     finale consignée avec la raison) — le κ d'origine demeure la
     pièce (jamais réécrit).
