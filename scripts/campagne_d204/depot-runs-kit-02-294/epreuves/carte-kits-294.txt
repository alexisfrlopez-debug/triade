POURQUOI AUCUN KIT NE PEUT EXISTER AVANT LA CAMPAGNE
------------------------------------------------------------------------------
Parce que chaque kit d'unité est le PRODUIT du workflow que la campagne
mesure. Le plan D204 (verrouillé, sha256 a78caf8c… consigné AVANT toute
mesure) ne compare pas deux logiciels : il compare DEUX FAÇONS DE
TRAVAILLER, et le kit est ce que chacune livre :

  — LE BRAS T (la notation scellée) : le labo LIT le contrat de couche I
    du bloc, ÉCRIT la notation À LA MAIN (chaque appel au modèle compté
    par compter_tokens.py, phase par phase), la construit, la
    round-trippe (R5), régénère l'oracle DEPUIS I, CRISTALLISE (dix
    rebuilds consécutifs identiques, R6) — le garde des arbres signés
    AVANT tout geste. Le kit naît de CE travail : la pièce dev + le
    scénario + les témoins.

  — LE BRAS C (le flux standard) : le MÊME agent écrit le source C du
    MÊME contrat, le compile gcc -O2, écrit ses tests comme le flux le
    pratique. Le kit : le binaire compilé + le même scénario adapté +
    les mêmes témoins.

Livrer les quatorze kits d'avance serait mesurer le vide : les tokens,
les temps de vérification, les défauts échappés — tout ce que la campagne
compte (M1, M2, M4) VIT dans la construction elle-même. Les kits ne se
prêtent pas : ils se construisent AU FIL, une unité à la fois.

L'ORDRE DE JEU D'UNE UNITÉ (qui fait quoi, dans l'ordre)
------------------------------------------------------------------------------
  1. LE LABO construit l'unité (le workflow complet, instrumenté,
     consigné) et LIVRE son kit au coffre /test — un dossier daté
     kit-unite-… portant ses EMPREINTES gravées ;
  2. VOUS, au GUI, onglet 1·KIT : CHOISIR le dossier du kit livré — le
     GUI recoupe ses empreintes gravées (une divergence, rien ne court) ;
  3. onglet 2·RUN : LANCER le lanceur officiel du kit — il court dans sa
     propre console, INTACT ; le dossier du run naît sur votre machine ;
     PUIS choisir ce dossier né (la pièce à renvoyer) ;
  4. onglet 3·TÉMOIN : ouvrir le témoin au bloc-notes, le DATER, le
     SIGNER DE VOTRE MAIN, renvoyer le dossier ENTIER au coffre /test —
     jamais automatisé (D99), le GUI n'écrit jamais au Drive ;
  5. aux onglets 4-7 : la ligne de carnet AU GESTE (M3), la livraison
     (M1, la cap tenue par le GUI), les défauts nommés avant correction,
     le chrono des commandes de vérification (M4) ;
  6. LE LABO recoupe le run revenu (le vert, ou l'écart nommé) — PUIS
     l'unité suivante commence.
