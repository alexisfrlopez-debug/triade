1. L'OBJET (le protocole que l'édition v0.19.3 a pré-enregistré)

|t| = 12.39 (tls13-02) et 5.19 (tls13-13) — consignés TELS QUELS — tous

répétition pré-enregistré : n ≥ 10 RUNS par N ∈ {60, 200, 400}, sur
≥ 2 MACHINES, l'empreinte CPU et la fréquence consignées, l'affinité de
cœur fixée, l'investigation des pics tls13-02/tls13-13 à N=200
PRÉ-ENREGISTRÉE (INVESTIGATION-PICS-N200.txt — les causes écrites AVANT

protocole REFUSÉ, jamais d'agrégat partiel).

2. LES QUATRE CIBLES (les blocs isolables — tls13-02/13 comprises)
--------------------------------------------------------------------------------
  tls13-02  la compression SHA-256 (le cœur du t=0 structurel — LE SECRET :
            le bloc 64 o comprimé) ;
  tls13-13  l'échelle X25519 (LE SECRET : LE SCALAIRE) ;
  tls13-16  le bloc AES-128 (LE SECRET : LA CLÉ) ;
  tls13-17  la multiplication GHASH (LE SECRET : X).
La limite consignée demeure : loupe-06 (md5) vit SOUS SESSION (contrat P1),
NON isolable sans l'application entière — la mesure pipeline de loupe.exe
appartient à une itération future du kit ; AUCUN chiffre n'existe pour lui.
Les cibles vivent dans cibles/ (l'IMAGE MÉMOIRE ÉTENDUE de la pièce scellée
proxy.exe — 69 632 o, chaque section à son RVA : les blocs ne sont PAS
autonomes, tls13-02 lit sa table K en .rdata par RIP-relatif — la leçon
vécue) + le manifeste. Le mesureur RECOUPE lui-même le sha256 de l'image
ET de chaque plage AVANT toute exécution.

4. LE PROTOCOLE DU RUN (la machine du développeur, DEUX machines distinctes)
--------------------------------------------------------------------------------
SUR CHAQUE MACHINE (≥ 2 : la machine de record + une seconde, nommées
machines A et B au témoin), dans le dossier du kit :
  1. CONSIGNER LA MACHINE au témoin AVANT le premier run (le champ exigé
     par la grille) : le modèle CPU COMPLET (l'empreinte CPU), la
     fréquence EFFECTIVE (base et turbo — l'état du turbo au BIOS noté à
     la main : le mesureur NE PEUT PAS le commander), l'OS, la version du
     compilateur ;
  2. COMPILER le mesureur DEPUIS LA SOURCE (la vérité) :
         cl /O2 dudect_v150.c
       ou gcc -O2 -o dudect_v150.exe dudect_v150.c -lm
     (le mesureur pose LUI-MÊME l'affinité sur le cœur 0) ;
  3. (recommandé) l'épreuve d'appel : recompiler/exécuter test_appel.c du
     kit v0.15.0 — FIPS « abc » EXACT attendu (la pièce mappée est la
     pièce scellée) ;
  4. LES RUNS — pour CHAQUE N ∈ {60, 200, 400}, DIX RUNS (n = 10, minimum
     pré-enregistré ; davantage admis, JAMAIS moins) :
         dudect_v150.exe cibles <N>
     chaque run écrit journal-dudect-<horodatage>.csv (cible, classe,
     iteration, cycles, secondes — LA PIÈCE) ; ranger chaque journal dans
     runs/<machine>/<cible>/N<N>/run<k>/journal-dudect-<horodatage>.csv
     (l'arborescence que l'agrégateur EXIGE — voir § 6) ;
  5. LE TÉMOIN PAR MACHINE : temoin-machine-<A|B>.txt (le modèle CPU, la
     fréquence effective, l'état du turbo, l'OS, le compilateur, le sha256
     de dudect_v150.c AVANT compilation, le sha256 du binaire compilé, les
     empreintes relues de cibles/) ;
  6. L'AGRÉGATION (le geste final) : python3 agregateur_dudect.py runs/
     — l'agrégateur VALIDE LA COMPLÉTUDE AVANT TOUT CALCUL : 2 machines ×
     4 cibles × 3 N × 10 runs, chaque journal complet (2N lignes par
     classe, les cycles présents), chaque témoin machine portant
     l'empreinte CPU ET la fréquence — TOUT MANQUE = REFUS (exit 2, la
     liste des manques) ; SEULEMENT ALORS il recalcule les t de Welch
     DEPUIS LES CYCLES des journaux (il ne fait confiance à AUCUNE
     console), agrège par la médiane et rend le verdict PAR CIBLE selon
     REGLE-JUGEMENT.txt.
