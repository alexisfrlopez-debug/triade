CE QU'IL FAIT (le geste en 1 clic) :
  1. Il porte LE KIT SCELLÉ EN LUI : les 10 pièces du paquet CORRECTIF2 du
     coffre, octet pour octet (le lanceur .bat, le LISEZMOI, les sources,
     dudect_v150.exe, test_appel.exe, l'extracteur, les cibles avec
     l'image scellée 0782d7e2…) — recoupées 10/10 dans l'exe livré.
  2. Il les écrit vers %LOCALAPPDATA%\TRIADE\kit-2-dudect en re-recoupant
     CHAQUE sha256 à CHAQUE run (fail-closed : REFUS nommé si un seul octet
     diverge — l'antivirus qui retirerait un exe de mesure est NOMMÉ,
     jamais un silence ; le coffre Drive a vécu ce faux positif le 12/11).
  3. Il archive les restes du run précédent vers archives\<horodatage>
     (D99 : jamais de mélange de runs).
  4. IL VIT LE VRAI LANCEUR DU KIT : cmd /c LANCER-KIT-2-DUDECT.bat — le
     .bat scellé fait TOUT (recoup de l'image scellée par sha256,
     recompilation depuis LA SOURCE si un compilateur vit, sinon les exe
     précompilés livrés, l'épreuve d'appel FIPS « abc », LE RUN N = 200 par
     défaut, le brouillon de témoin). Sa console ENTIÈRE est capturée dans
     run-console-<horodatage>.txt puis affichée telle quelle. Vous pouvez
     passer votre N : lancez l'exe avec l'argument (ex. « 400 », minimum 60
     — validé par le lanceur du kit lui-même).
  5. IL CONSTRUIT LES PREUVES : preuves-kit2-dudect-<horodatage>.zip sur le
     BUREAU (console entière + journal-dudect-*.csv + sortie-run.txt +
     sortie-appel.txt + témoin-dudect-BROUILLON.txt + DEPOT.txt).
  6. IL OUVRE l'explorateur SUR LE ZIP et le coffre /test du Drive dans le
     navigateur (dossier « Triade » → « test ») : DEPOSEZ le zip — VOTRE
     geste, comme au GUI v1 et à l'APK. Puis, à votre main : complétez le
     témoin (l'état EFFECTIF du turbo, vos observations mêmes défavorables

  — l'exe NE MESURE RIEN et ne modifie JAMAIS le kit : la mesure vit dans

    les sorties et codes de sortie sont LES LEURS ;
