LE CONTRAT DE COUCHE I (mot pour mot) :
loupe-18 · quitter : la sortie propre, aucun octet perdu, aucune fuite · révision 1
Intention : la sortie propre — LE DOUBLE-GESTE GARANTIT : si la marque
sale est posée, le PREMIER Alt+F4 est REFUSÉ NOMMÉMENT (la barre dit
« MODIFIÉ — Alt+F4 encore pour quitter sans sauver, Ctrl+S pour
sauver », le coup s'entend) et SEUL LE SECOND TRANSCHE (la volonté
délibérée, deux fois nommée — jamais une perte d'un seul geste) ;
sinon : DestroyWindow, WM_DESTROY → la session close (loupe-03 : la
poignée rendue, les zones d'hygiène vidées), PostQuitMessage (la
boucle héritée win-03 rend), WinMain retourne, ExitProcess(0) —
AUCUNE poignée pendante, AUCUN contexte mort, AUCUNE fuite : la
sortie est aussi propre que l'entrée était vraie.
Contrat :
  pre  : P1 appelée par la procédure (loupe-09 Q3) sur WM_CLOSE
             (Alt+F4 ou le menu système) ou, chez WM_DESTROY, par la
             fin de fenêtre ; P2 l'état du cadre fait foi (sale,
             refus_quitter — les DEUX champs de loupe-04 P1).
  post : Q1 WM_CLOSE AVEC marque sale ET refus_quitter = 0 →
             refus_quitter = 1, verdict -5 (L'ORDRE REFUSÉ EN
             L'ÉTAT), la barre nomme « MODIFIÉ — Alt+F4 encore pour
             quitter sans sauver, Ctrl+S pour sauver », MessageBeep
             (le refus s'entend) — la fenêtre DEMEURE, rien n'est
             perdu ;
         Q2 WM_CLOSE AVEC marque sale ET refus_quitter = 1 (le second
             geste) OU marque propre → DestroyWindow (la fin demandée
             — l'utilisateur a tranché : sauver était à lui) ;
         Q3 WM_DESTROY : loupe-03 (la session close PROPREMENT : la
             poignée rendue, le cadre vierge, le journal ABANDONNÉ
             DÉLIBÉRÉMENT — le double-geste l'a nommé, les octets
             non sauvés sont une VOLONTÉ, pas une perte), puis
             PostQuitMessage(0) — la boucle héritée win-03 rend,
             WinMain retourne, ExitProcess(0) ;
         Q4 rax = 0 aux deux chemins de passage ; le chemin refusé
             rend -5 (le verdict nommé monte à la barre — l'écran
             nomme ce qu'il refuse).
  inv  : I1 LA GARDE EST INVARIANTE : la perte d'octets non sauvés
             exige DEUX gestes (le premier REFUSÉ nommément — la
             garde ré-armée par loupe-16 à CHAQUE écriture et levée
             par loupe-17 à CHAQUE sauvegarde réussie : le réseau
             des trois blocs la tient, l'oracle à scénarios le
             prouve par tous les chemins) ;
         I2 la sortie ne SAUVEGARDE JAMAIS elle-même (la sauvegarde
             est un geste explicite de loupe-17 — quitter ne décide
             JAMAIS à la place de l'utilisateur) ;
         I3 AUCUNE fuite : la poignée close (loupe-03), le contexte
             de peinture TOUJOURS rendu (EndPaint chez loupe-10, y
             compris à l'avortement — E2 de loupe-10), la file
             quittée (PostQuitMessage UNE fois), le code de sortie
             0 (le succès : même l'abandon délibéré est une sortie
             PROPRE) ;
         I4 l'IAT fermée du bloc (DestroyWindow, PostQuitMessage,
             MessageBeep) — la clôture de session vit chez loupe-03,
             le processus meurt chez loupe-09 (ExitProcess) ;
             registres non volatils rendus ; NOP, 0x90.
Échecs :
  E1 : WM_CLOSE sur marque sale non encore refusée → verdict -5 (LE
       REFUS NOMMÉ — la barre porte la phrase, le coup s'entend) :
       c'est L'ÉCHEC QUI GARDE, la sanction est la protection.
Vecteurs :
  V1 : scénario — Alt+F4 SANS marque sale : la sortie directe (la
       session close, la file quittée, ExitProcess(0) — les appels
       comptés un à un) (couvre Q2, Q3, Q4).
  V2 : scénario — LE DOUBLE-GESTE : trois octets édités, Alt+F4 :
       le refus -5, la fenêtre DEMEURE, la barre porte la phrase,
       le beep sonne ; Alt+F4 encore : la sortie SANS sauvegarde
       (le journal abandonné délibérément — le fichier au disque

  V3 : scénario — LE RÉSEAU DE LA GARDE : Alt+F4 refusé, Ctrl+S (la
       sauvegarde lève refus_quitter), Alt+F4 : la sortie DIRECTE

       Alt+F4 refusé, une NOUVELLE écriture (la garde ré-armée),

  V4 : rejet — le verdict -5 monte à la barre (l'écran attendu le

  V5 : falsification — la garde mutée (refus_quitter jamais levé

LES CONVENTIONS DE NOTATION DU DOMAINE :
- la feuille pure : arguments seuls, aucune entrée IAT, aucun état détenu ;
- ABI msx64 : rcx, rdx, r8, r9 puis la pile ; les non-volatils (rbx, r12-r15)
  sauvegardés par le bloc ; le cadre aligné à 16 ; l'appelant réserve le
  shadow space de 32 octets ;
- la notation x86-64 : une instruction par ligne, mnémonique puis opérandes ;
  les sauts aux cibles absolues (0x…), les appels aux adresses du plan ;
  les commentaires préfixés « ; » ; l'en-tête commenté du bloc porte son
  identité (nom, spec, slot, taille, étiquettes résolues, appels directs).

LE FORMAT DE RÉPONSE HUNK (obligatoire, fail-closed — le client applique,
reconstruit et confronte par round-trip exact ; quatre refus nommés :
HORS-FORMAT, HUNK-INCONNU, CONTEXTE-DIVERGENT, ROUND-TRIP-DIVERGENT).
LA GRAMMAIRE :
@@ hunk <k>          (k = 1, 2, 3… le rang du hunk, en ordre)
base: <UNE ligne exacte du texte courant — LE PREMIER POINT DU CHANGEMENT>
- <une ligne retirée à partir de l'ancre>   [0 ou plus]
+ <une ligne insérée au même point>         [1 ou plus]
… (les hunks suivent, chacun commence par « @@ hunk k »)
FIN-HUNKS
LA SÉMANTIQUE DE L'ANCRE : l'ancre est la ligne OÙ LE CHANGEMENT SE PRODUIT.
Si le hunk retire des lignes, la PREMIÈRE ligne « - » EST L'ANCRE ELLE-MÊME
(la ligne remplacée, répétée) et les retraits suivent dans l'ordre À PARTIR
DE L'ANCRE — elles sont remplacées par les lignes « + ». Si le hunk ne
retire RIEN, l'ancre est la ligne APRÈS laquelle l'insertion se fait.
UN EXEMPLE COMPLET (remplacer « mov eax, 5 » par « mov eax, 6 » puis
insérer « nop » après « pop rbx ») :
@@ hunk 1
base: mov eax, 5
- mov eax, 5
+ mov eax, 6
@@ hunk 2
base: pop rbx
+ nop
FIN-HUNKS
RIEN d'autre dans la réponse — aucun texte hors hunks, aucune politesse,
la dernière ligne est exactement « FIN-HUNKS ».

UN EXEMPLE COMPLET DE RÉPONSE D'AJOUT (le bloc qui vérifie un tampon non vide et rend sa taille — la réponse ENTIÈRE, caractère pour caractère, telle que le client l'attend) :

base: ; --- LE CORPS DU BLOC ICI ---
+ test rcx, rcx

@@ hunk 2
base: add rsp, 0x20
+ nop
FIN-HUNKS
(REMARQUE : la réponse ci-dessus est TOUTE la réponse — elle commence à « @@ hunk 1 » et finit à « FIN-HUNKS », AUCUNE ligne de la notation du gabarit n'est re-dumpée, AUCUNE explication.)
REQUÊTE : compose le bloc et rends UNIQUEMENT les hunks qui insèrent le corps dans le gabarit — la première ligne de ta réponse est EXACTEMENT « @@ hunk 1 », la dernière exactement « FIN-HUNKS ».
