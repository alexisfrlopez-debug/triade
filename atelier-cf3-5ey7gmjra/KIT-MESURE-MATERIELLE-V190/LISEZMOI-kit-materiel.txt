LE PROTOCOLE PRÉ-ENREGISTRÉ (chaque geste AVANT toute donnée)
═════════════════════════════════════════════════════════════════════════════
P1 LES RUNS : n ≥ 10 exécutions INDÉPENDANTES du mesureur par valeur de N
   — chaque exécution un processus frais (l'affinité re-posée, l'échauffe-
   ment re-vécu), la graine de chaque exécution CONSIGNÉE dans le témoin
   (l'ordre des tirages reproductible) ; JAMAIS une exécution unique
   habillée de dix mensonges.
P2 LES VALEURS DE N : N = 60 (le contrôle structurel — le pendant des
   60/classe de l'instrument d'émulation hash-vérifié) ET N = 200 (la
   valeur du run signé du 13/11 — L'INVESTIGATION DES PICS porte ici) ;
   N = 400 (la seconde valeur du run signé)demeure au protocole pour la
   comparaison exacte au témoin existant.
P3 LES MACHINES : ≥ 2 machines (la machine Windows du développeur — celle
   du témoin signé du 13/11 — ET une seconde machine : l'autre Windows du
   dépôt à deux machines, D204, ou la machine tiers du scénario Loupe) ;
   chaque machine porte son EMPREINTE consignée : le modèle CPU, la
   fréquence NOMINALE et l'état EFFECTIF du turbo/gouverneur, l'OS, la
   charge au moment du run (le témoin l'exige — le run v0.15.0 le fit).
P4 LA FRÉQUENCE CPU FIXÉE : le gouverneur à performance constante (ou le
   turbo désactivé au BIOS) AVANT la série — l'état EFFECTIF consigné au
   témoin (jamais « désactivé si possible » silencieux : l'état lu, nommé).
P5 L'AFFINITÉ CORE : un cœur unique par exécution (le mesureur la pose :
   SetThreadAffinityMask / sched_setaffinity — le mécanisme scellé) ; le
   cœur CHOISI consigné (les pics d'un cœur partagé avec une interruption
   sont une cause nommée, pas une découverte).
P6 L'INVESTIGATION DES PICS tls13-02/tls13-13 À N=200 : le run signé du
   13/11 porta DEUX cibles au-dessus du seuil à N=200 (12,39 et 5,19 —
   les valeurs CONSIGNÉES AU TÉMOIN, jamais réinterprétées) ; la présente
   pré-enregistre L'INVESTIGATION : à N=200, n≥10 exécutions par machine,
   la DISTRIBUTION des t par exécution (pas seulement la moyenne : le
   nombre d'exécutions au-dessus du seuil, l'étendue, la médiane) ; les
   causes candidates NOMMÉES AVANT les données : (a) le bruit d'horloge
   d'une exécution unique (le t de Welch au seuil 5 sur un échantillon
   unique : la probabilité de faux positif non nulle — la répétition la
   tranche) ; (b) l'interruption/la migration du cœur (l'affinité posée
   mais le cœur partagé) ; (c) UN VRAI ÉCART de temps constant sur les
   deux cibles (la conclusion que les données seules peuvent imposer —
   si la répétition le tient, l'écart est NOMMÉ au manuscrit et la
   mitigation au commandement du développeur) ; AUCUNE cause n'est
   élue d'avance : les données tranchent, le protocole les attend.
P7 LE JUGEMENT : une cible est dite À L'ÉCART si la MÉDIANE des t des
   n≥10 exécutions dépasse le seuil 5 sur une machine (le critère
   pré-enregistré) ; le rapport final porte PAR cible PAR machine PAR N :
   la liste des t, la médiane, l'étendue, le verdict AU CRITÈRE — la
   table des statuts du manuscrit porte le résultat AU STATUT EXACT
   (« measured (n runs, m machines) » — jamais « constant time proven »,
   la discipline du témoin v0.15.0 reconduite).
P8 L'AGRÉGATION : agreger_mesures_v190.py (ci-présent) lit les journaux
   CSV du mesureur scellé (journal-dudect-*.csv — le format inchangé),
   calcule les médianes/étendues PAR cible/machine/N et tranche au
   critère P7 — l'outil REFUSE tout fichier manquant ou toute ligne
   imputable (échec fermé : aucune valeur fabriquée, aucune ligne
   inventée, le moindre écart un REFUS nommé).
