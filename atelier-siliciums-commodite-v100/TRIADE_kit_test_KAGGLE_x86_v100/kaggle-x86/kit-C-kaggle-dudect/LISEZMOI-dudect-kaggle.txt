CE QUE CE KIT MESURE (et ce qu'il refuse) :
  — les QUATRE cibles SCELLÉES de cibles/proxy-image.bin (la pièce
    scellée v0.15.0, l'image mémoire étendue posée par l'extracteur du
    kit-2) : tls13-02 (compression SHA-256), tls13-13 (échelle X25519),
    tls13-16 (bloc AES-128), tls13-17 (GHASH). L'image est RECOUPÉE
    (sha256 de l'image entière + sha256 de CHAQUE plage de cible contre
    le manifeste) AVANT toute exécution, ET l'épreuve FIPS « abc » est
    exigée DE LA PIÈCE SCELLÉE ELLE-MÊME (tls13-02 doit rendre le
    condensé exact, puis la mutation d'un octet de sa table K — EN
    MÉMOIRE SEULEMENT, la carte est MAP_PRIVATE, le fichier sur disque
    est intouchable — doit DIVERGER le condensé, puis la restauration
    doit le rendre exact) : l'image exécutée est la pièce recoupée,
    RIEN d'autre n'est exécuté ;
  — loupe.exe et moteur-shani.bin (les autres pièces scellées) sont
    HORS PÉRIMÈTRE de ce kit : leurs empreintes sont CITÉES au binaire,
    elles ne sont pas mesurées ici (chacune a son kit) ;
  — le binaire est compilé par LE MÊME GESTE : compilé SUR PLACE depuis
    la source ouverte (aucun exe précompilé ne vit dans ce kit, rien ne
    peut être retiré par un scanner).

LE PROTOCOLE KAGGLE-X86-1 (l'équation pré-enregistrée, l'égalation du
COLLAB-X86-1) :
  Les CIBLES, dans cet ordre :
    1. eq-constant     le CONTRÔLE POSITIF : la comparaison de 32 octets
                       par OU masqué — aucun branchement sur le secret.
                       ATTENDU : aucune divergence au seuil (une
                       divergence serait un RÉSULTAT précieux : D189,
                       consigner tel quel).
    2. eq-branchue     le CONTRÔLE NÉGATIF : la sortie au premier octet
                       divergent — LE FAUX PATRON. ATTENDU : DIVERGENCE.
                       Si elle ne diverge PAS : l'instrument est
                       CONTESTÉ, le verdict le nomme (un instrument non
                       éprouvé ne mesure rien).
    3. sha256-logiciel la compression SHA-256 logicielle d'un bloc de 64
                       octets (l'état AMONT est l'IV, le bloc est LE
                       SECRET). ATTENDU : aucune divergence.
    4. sha256-x86-shani la compression par les INSTRUCTIONS MATÉRIELLES
                       SHA-NI. VIT seulement si le noyau expose le
                       drapeau « sha_ni » ET que le compilateur a accepté
                       -msha -mssse3 -msse4.1 — sinon REFUS NOMMÉ, le
                       reste du run vit. ATTENDU : aucune divergence.
    5. tls13-02        SCELLÉE : la compression SHA-256 de la pièce —
                       l'état AMONT est l'IV, le bloc 64 est LE SECRET.
    6. tls13-13        SCELLÉE : l'échelle X25519 — le scalaire est LE
                       SECRET, u est l'auxiliaire fixe de la cible.
    7. tls13-16        SCELLÉE : le bloc AES-128 — les 176 octets de
                       clés sont LE SECRET, l'entrée est l'auxiliaire.
    8. tls13-17        SCELLÉE : le GHASH GF(2^128) — X est LE SECRET,
                       Y l'auxiliaire.
  Les CLASSES, deux par cible, ÉCHANTILLONS ENTRELACÉS (à CHAQUE
  itération la première classe vit puis la seconde — le secret régénéré
  hors mesure) :
    — comparaisons : la classe EGAL contre la classe DIVERGENT ;
    — compressions et cibles scellées : la classe SECRET-FIXE contre la
      classe SECRET-ALÉATOIRE (l'invariance de données).
  L'ÉQUATION : échauffement 100 paires par cible (résultats jetés) ; un
  échantillon mesure un LOT d'appels (l'amplification pré-enregistrée) :
  LOT=512 pour eq-constant, eq-branchue, tls13-16 et tls13-17 ; LOT=64
  pour sha256-logiciel, sha256-x86-shani et tls13-02 ; LOT=1 pour
  tls13-13 ; N échantillons par classe, N=60 puis N=200 puis N=400 DANS
  CET ORDRE (trois runs complets) ; la statistique est le t de Welch sur
  les ticks, le seuil |t| > 5 (les mêmes paramètres que le kit-2, le
  kit-B, le kit-C COLLAB et l'édition structurelle v0.11.0).
  LE COMPTEUR : RDTSC sur x86-64 — la grandeur est nommée « ticks »,
  JAMAIS « cycles » (la fréquence du TSC n'est pas lue : les drapeaux
  constant_tsc/nonstop_tsc sont constatés et nommés, la colonne
  « secondes » du csv vit en contrepoint CLOCK_MONOTONIC).
  L'ÉPREUVE PRÉALABLE (fail-closed, TROIS lecteurs) : le condensé FIPS
  180-4 « abc » EXACT exigé du lecteur LOGICIEL, du lecteur SHA-NI (si
  présent) ET DE LA PIÈCE SCELLÉE tls13-02 (avec l'adversaire de
  mutation K) AVANT toute mesure — un lecteur faux est un REFUS : rien
  n'est mesuré.

LE RUN (dans un notebook Kaggle — l'ordre exact des cellules vit aussi
au A-LIRE-EDITION-KAGGLE.txt) :

     race avec l'accélérateur ; le kit mesure le CPU, l'accélérateur
     est constaté).
  1. téléversez TRIADE_kit_test_KAGGLE_x86_v100.zip dans les INPUTS du
     notebook (bouton « + Add Input » → « Upload » → Dataset) ;
     le zip vit alors sous /kaggle/input/<nom-du-dataset>/ ;
  2. cellule :
       !cp /kaggle/input/*/TRIADE_kit_test_KAGGLE_x86_v100.zip .
       !unzip -q TRIADE_kit_test_KAGGLE_x86_v100.zip -d /kaggle/working
  3. cellule :
       !bash /kaggle/working/TRIADE_kit_test_KAGGLE_x86_v100/COMMENCER-ICI.sh
     — le lanceur vérifie les empreintes du paquet, INSTALLE gcc par
       apt-get s'il manque, COMPILE la pièce sur cette machine depuis
       la source (la source est la vérité), vit l'épreuve FIPS des
       trois lecteurs, puis les TROIS runs N=60, N=200, N=400 dans
       l'ordre imposé ;

     kit-C-kaggle-dudect/ — RÉCUPÉREZ-LE AVANT LA FIN DE LA SESSION
     (onglet Output du panneau droit, ou en cellule :
       import shutil
       shutil.copy('<chemin-imprimé-par-le-run>.zip', '/kaggle/working')
     puis téléchargement) ; SAUVEGARDEZ LE NOTEBOOK (Save Version) pour
     que /kaggle/working vive dans la version enregistrée.
