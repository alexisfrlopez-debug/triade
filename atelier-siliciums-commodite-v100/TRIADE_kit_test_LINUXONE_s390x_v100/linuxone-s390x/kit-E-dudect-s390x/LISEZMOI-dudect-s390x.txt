LE PROTOCOLE LINUXONE-S390X-1 (l'équation pré-enregistrée) :
  Les CIBLES, dans cet ordre :
    1. eq-constant     le CONTRÔLE POSITIF de l'instrument : la
                       comparaison de 32 octets par OU masqué — aucun
                       branchement sur le secret. ATTENDU : aucune
                       divergence au seuil. (Une divergence serait un
                       RÉSULTAT précieux : D189, consigner tel quel.)
    2. eq-branchue     le CONTRÔLE NÉGATIF : la sortie au premier octet
                       divergent — LE FAUX PATRON. ATTENDU : DIVERGENCE
                       — la preuve que l'instrument détecte les fuites.
                       Si elle ne diverge PAS : l'instrument est
                       CONTESTÉ sur cet échantillon, le verdict le
                       nomme.
    3. sha256-logiciel la compression SHA-256 logicielle d'un bloc de 64
                       octets (la même mécanique que la cible tls13-02
                       du kit-2 : l'état AMONT est l'IV, le bloc est LE
                       SECRET). ATTENDU : aucune divergence.
  Les CLASSES, deux par cible, ÉCHANTILLONS ENTRELACÉS (à CHAQUE
  itération la première classe vit puis la seconde — le secret régénéré
  hors mesure) :
    — comparaisons : la classe EGAL (le secret est la copie de
      l'étalon) contre la classe DIVERGENT (un secret frais) ;
    — compression : la classe SECRET-FIXE contre la classe
      SECRET-ALÉATOIRE (l'invariance de données).
  L'ÉQUATION : échauffement 100 paires par cible (résultats jetés) ; un
  échantillon mesure un LOT d'appels (l'amplification adaptée à
  l'horloge du noyau en nanosecondes, PRÉ-ENREGISTRÉE) : LOT=4096 pour
  les comparaisons, LOT=64 pour la compression ; N échantillons par
  classe, N=60 puis N=200 puis N=400 DANS CET ORDRE (trois runs
  complets) ; la statistique est le t de Welch sur les ticks, le seuil
  |t| > 5 (les mêmes paramètres que le kit-2, le kit-B et le kit-C).
  LE COMPTEUR : CLOCK_MONOTONIC en NANOSECONDES sur s390x — l'horloge
  du noyau, NOMMÉE, jamais déguisée en cycles (sur l'hôte x86-64 du
  laboratoire : TSC, la voie de l'AUTOTEST — aucun statut terrain n'en
  découle). Contrepoint : la colonne « secondes » du csv.
  L'ÉPREUVE PRÉALABLE : le condensé FIPS 180-4 « abc » EXACT exigé du
  lecteur logiciel AVANT toute mesure — un lecteur faux est un REFUS :
  rien n'est mesuré.

LE RUN (sur le shell Linux s390x de la porte choisie — Z Xplore ou
toute autre, voyez A-LIRE-EDITION-LINUXONE.txt) :
  1. téléversez les TROIS fichiers du kit dans votre dossier
     (dudect_s390x.c, scenario-dudect-s390x.py,
     lancer-kit-E-dudect-s390x.sh — AUCUN binaire ne voyage) ;
  2. tapez   bash lancer-kit-E-dudect-s390x.sh
     — le lanceur trouve Python et gcc (il tente l'installation par le
     gestionnaire de paquets s'il peut — REFUS NOMMÉ sinon), COMPILE la
     pièce SUR CETTE MACHINE depuis la source (la source est la
     vérité), vit l'épreuve FIPS, puis les TROIS runs N=60, N=200,
     N=400 dans l'ordre imposé ;
  3. quelques minutes ; le réseau ne sert qu'à l'installation éventuelle
     des paquets ; aucun droit particulier.

LA LECTURE HONNÊTE (à lire AVANT de s'inquiéter d'un verdict) :
  — |t| > 5 = dépendance AU SEUIL sur CET échantillon, consignée telle
    quelle ;
  — |t| <= 5 = aucune divergence au seuil sur cet échantillon, CETTE
    machine — jamais « temps constant prouvé » ;
  — le contrôle négatif eq-branchue DOIT diverger (sinon l'instrument
    est CONTESTÉ — nommé) ;
  — le silicium Z gouverne sa cadence : le témoin constate ce que la
    machine dit d'elle-même, rien de plus ;
  — un écart nommé est un RÉSULTAT aussi précieux qu'un vert (D189) :
    rapportez-le tel quel.
