POURQUOI CETTE ÉDITION. Colab et Kaggle prêtent des notebooks : UNE
machine à la fois, MUTUALISÉE, session éphémère. GitHub Actions prête
AUTRE CHOSE : TROIS siliciums d'un seul geste — les runners du dépôt
public sont gratuits, sans limite de minutes, et la matrice vit sur du
hardware VRAIMENT différent :
  — ubuntu-latest      le serveur x86-64 (un autre Xeon/EPYC que le
                        Colab de l'Entrée 426) ;
  — ubuntu-24.04-arm   le serveur ARM64 (une famille serveur, une
                        AUTRE que le Cortex du téléphone) ;
  — macos-latest       L'APPLE SILICON (la famille M du runner
                        courant — la première fois du silicium Apple
                        dans la campagne : le sysctl du témoin nomme la
                        puce EXACTE, FEAT_SHA256 possible, l'épreuve FIPS
                        décidera).
LA QUESTION de l'Entrée 421 y trouve son discriminateur ÉTENDU : le
kit-C (la question machine-ou-code, les QUATRE SCELLÉES) sur un
QUATRIÈME x86-64 ; l'équation du kit-B sur un QUATRIÈME ARM64 ; et le
silicium Apple en prime. Les runs sont étiquetés AUTOTEST-DISTANT :
le geste est celui du LABO (le workflow du dépôt) sur un silicium
RÉEL — la hiérarchie demeure (le banc contrôlé référence, ces runs
des lectures de commodité, JAMAIS le run terrain du développeur).

COMMENT LE GESTE VIT (deux voies) :
  VOIE 1 (la voie du labo, VÉCUE à la livraison) : le workflow vit AU
    DÉPÔT (.github/workflows/triade-siliciums-commodite.yml) — il se
    déclenche au push qui touche l'atelier, OU À LA MAIN (onglet
    « Actions » du dépôt → « TRIADE — siliciums de commodité » →
    « Run workflow »). Les trois jobs vivent leurs kits (quelques
    minutes chacun), puis le job « depot-des-preuves » committe les
    réceptacles au dépôt sous
    atelier-siliciums-commodite-v100/preuves-actions/<job>/ — le
    maître les lit dans le dépôt, ou télécharge les artefacts depuis
    la page du run.
  VOIE 2 (la voie du terrain, si le maître veut VIVRE le geste
    lui-même sur SA session) : téléversez
    TRIADE_kit_test_ACTIONS_multisilicium_v100.zip sur n'importe quel
    Linux de commodité, dézippez, et vivez l'enveloppe de VOTRE choix
    (elle fonctionne hors CI aussi) :
        bash TRIADE_kit_test_ACTIONS_multisilicium_v100/actions-x86/kit-C-actions-dudect/lancer-kit-C-CI.sh
    (l'étiquette dit AUTOTEST-DISTANT : barrez-la de votre main au
    témoin si CE run est le vôtre — le geste du kit-C COLLAB vit
    pareil pour le terrain.)

CE QUE CETTE ÉDITION REFUSE (le périmètre demeure intouché) : les
pièces scellées v0.15.0 sont x86-64 Windows — REFUSÉES PAR NATURE sur
les siliciums ARM64 (empreintes citées, jamais mesurées) ; sur le job
x86-64, SEULE proxy-image.bin vit (recoupée avant exécution, lecture
seule, périmètre v0.15.0 intact). Windows ARM64 (runner gratuit en
préversion publique) : REFUS NOMMÉ v1.0.0 (le portage msys2/mingw
demanderait une itération). macOS Intel : REFUS NOMMÉ v1.0.0 (le geste
prioritaire était le silicium APPLE, pas un quatrième x86). Le couloir
VAES/AES-GCM (P5), le moteur d'oracle : le poste réel.
